# Engineering Ensemble Robustness: A Blueprint for Mitigating Multicollinearity and Miscalibration via GLM Margins, CatBoost CTR, and Constrained Meta-Learning

## Two-Stage Residual Boosting with GLM Margins

The development of a high-performance machine learning ensemble often hinges on the careful orchestration of its constituent models to minimize redundancy and maximize complementary signal. In the context of a large-scale Kaggle competition with a dataset ranging from 700k to 830k rows, computational efficiency and resistance to overfitting become paramount. The proposed strategy of implementing a Standard Two-Stage Residual Boosting approach using leak-free out-of-fold (OOF) margins from a Generalized Linear Model (GLM) represents a sophisticated architectural choice designed to directly address the twin challenges of model collinearity and inefficient signal propagation. This methodology elegantly partitions the learning task: a GLM captures the primary linear and monotonic relationships within the data, while subsequent Gradient Boosted Decision Trees (GBDTs) focus exclusively on modeling the complex, non-linear interactions that the initial model has failed to explain. This separation not only creates a more robust and less correlated set of base learners but also provides a computationally tractable path toward a powerful stacked ensemble, avoiding the prohibitive costs and instability associated with more complex, end-to-end optimization schemes. The rationale for this approach is rooted in both practical constraints and sound statistical principles. Joint end-to-end differentiable optimization, which would involve tuning all models simultaneously through hundreds of full GBDT loops, is computationally infeasible on the resource-constrained environment of Kaggle GPUs and is highly susceptible to meta-overfitting, where the ensemble learns the noise in the validation set rather than generalizable patterns [[14](https://www.machinelearningmastery.com/stacking-ensemble-machine-learning-with-python/), [24](https://www.machinelearningmastery.com/out-of-fold-predictions-in-machine-learning/)]. The two-stage method circumvents this complexity by decoupling the modeling of additive effects from the modeling of interaction effects, thereby simplifying the overall optimization landscape.

The first stage of this architecture involves fitting a regularized GLM, specifically a Logistic Regression model with L2 regularization, across multiple folds of the training data [[15](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.nnls.html)]. The use of 5-fold Cross-Validation (CV) is critical to ensure that the resulting predictions are leak-free, meaning they are generated on unseen data for each sample, thus preventing optimistic bias when these predictions are later used as inputs for other models [[24](https://www.machinelearningmastery.com/out-of-fold-predictions-in-machine-learning/)]. During this stage, careful feature engineering is essential to align with the intended role of the GLM. Continuous features such as `Age` and `Flight Distance` should not be passed to the model in their raw form. Instead, they should be transformed using natural splines or quantile-based binning. This preprocessing allows the GLM to flexibly capture non-linear but monotonic relationships without being burdened by the task of discovering complex interactions, a domain where GBDTs excel. For instance, a spline transformation can model a U-shaped or inverted U-shaped relationship between age and flight delay likelihood, providing a strong baseline approximation. Categorical features, on the other hand, are best handled through standard one-hot encoding, creating binary indicator variables for each category level. This ensures the GLM can assess the additive effect of each category relative to a baseline. The output of this stage is a vector of logit margins, $\eta_i = \mathbf{x}_i^T \boldsymbol{\beta}$, for every sample $i$ in the dataset. These margins represent the predicted log-odds generated by the best possible linear and spline-based combination of the input features.

The second stage leverages these OOF-generated margins as a foundational starting point for training the GBDT models, namely XGBoost and LightGBM. This is achieved by passing the margin values directly to the GBDT constructors via the `base_margin` parameter in XGBoost and the `init_score` parameter in LightGBM <Conversation History>. This mechanism is not merely a convenience; it is a fundamental aspect of the boosting algorithm itself. In gradient boosting, the initial weak learner is typically a simple model that predicts the global mean or log-odds of the target variable [[20](https://medium.com/@joachimiak.krzysztof/the-forgotten-initial-estimator-in-gbms-65d6c8354572)]. XGBoost refers to this as `base_score` [[22](https://xgboost.readthedocs.io/en/stable/parameter.html)], while CatBoost uses `boost_from_average=True` to achieve a similar initialization [[20](https://medium.com/@joachimiak.krzysztof/the-forgotten-initial-estimator-in-gbms-65d6c8354572)]. However, the `base_margin` functionality in XGBoost elevates this concept from a single scalar value to a vector of sample-specific initial predictions [[21](https://xgboost.readthedocs.io/en/latest/tutorials/intercept.html)]. When `base_margin` is provided, the GBDT training process is effectively "boosting from a prediction." The model treats the supplied margins as the initial estimates for all instances. Consequently, the subsequent trees are trained not to predict the original target variable from scratch, but to predict the residuals—the differences between the true target and the initial GLM-based predictions. Each tree splits the data and assigns leaf values that best correct the errors made by the cumulative sum of all previous trees, including the initial GLM prediction. This forces the GBDT to specialize in capturing the non-linear interaction effects and higher-order complexities that the linear model could not approximate, leading to a more efficient and focused learning process. The mathematical equivalence to this workflow is that the GBDT is optimizing the same loss function (e.g., log-loss for classification) but starting its search from a sophisticated initial guess rather than a naive constant [[21](https://xgboost.readthedocs.io/en/latest/tutorials/intercept.html)].

This two-stage design yields several significant benefits that directly contribute to building a more robust and effective ensemble. Firstly, it intrinsically reduces collinearity among the base models. The predictions from the Stage 1 GLM and the Stage 2 GBDT are inherently less correlated because they are built on different assumptions and operate on different signals. The GLM excels at additive effects, while the GBDT specializes in non-linear residuals. This orthogonality prevents the "crowding" phenomenon where multiple highly correlated models provide redundant information to the meta-learner, which can lead to unstable weighting schemes and poor generalization. Secondly, it improves interpretability and debugging. By isolating the linear component into a transparent GLM, one gains insight into the most dominant, straightforward relationships in the data. The performance of the GBDT can then be interpreted as a measure of the importance of the non-linear structure that remains after accounting for these linear trends. Thirdly, it enhances computational efficiency. Training a single, highly complex GBDT might require many iterations and extensive tuning to learn both linear and non-linear patterns simultaneously. By offloading the simpler linear task to a fast and stable GLM, the GBDT can converge faster and with fewer resources, focusing its computational power on the more challenging aspects of the problem. Finally, this approach creates a cleaner, more structured foundation for the next level of the ensemble stack. When the OOF predictions from the GLM and the GBDT are passed to a meta-model, they represent two distinct and complementary views of the data, making it easier for the meta-learner to find an optimal way to combine them.

A crucial detail in the implementation of this two-stage process is the preparation of the feature set for the GLM. As mentioned, continuous features must be preprocessed. Using natural splines, for example via `patsy` or `statsmodels`, allows for piecewise polynomial fitting that is smooth and flexible, capturing non-linearities without the discontinuities of simple binning. Quantile binning achieves a similar goal by dividing the data into bins with an equal number of samples, which can be particularly useful if the relationship is expected to be step-wise. For both approaches, the key is to avoid feeding raw continuous variables to the GLM, which would force it to rely solely on linear terms and potentially miss important trends. For categorical features, the decision to use one-hot encoding is standard practice unless the cardinality is extremely high, in which case alternative encodings like target encoding or frequency encoding might be considered. Once the GLM is trained on these engineered features with L2 regularization (to penalize large coefficients and prevent overfitting), its OOF predictions are collected across all CV folds. These predictions form the `base_margin` array, which must have the same length as the number of training samples. When constructing the DMatrix for XGBoost, this array is passed directly to the `base_margin` argument <Conversation History>[[21](https://xgboost.readthedocs.io/en/latest/tutorials/intercept.html)]. Similarly, for LightGBM, the corresponding array is passed to the `init_score` argument upon training <Conversation History>. It is vital to ensure that the link function is consistent; since the GLM produces logit margins, the subsequent GBDT should be trained with an objective function compatible with log-loss (e.g., `objective='binary:logistic'` in XGBoost).

In summary, the two-stage residual boosting approach using GLM margins is a powerful and principled technique for constructing ensembles. It systematically decomposes the predictive task into manageable sub-problems, leveraging the strengths of different model classes at each stage. The GLM establishes a strong, interpretable linear baseline, while the GBDT focuses on correcting its weaknesses by modeling complex residuals. This process breaks down the monolithic challenge of learning from raw features into a sequence of more focused tasks, which is computationally cheaper, less prone to overfitting, and results in a more diverse and robust set of base learners for the final stacking phase. The resulting low-correlation predictions provide a fertile ground for a well-calibrated and high-performing meta-learner.

## Leveraging CatBoost's Target Statistics to Break Collinearity

When faced with extreme multicollinearity between base models, such as the near-perfect correlation of $r = 0.9981$ observed between LightGBM and CatBoost in this scenario, simply adjusting hyperparameters becomes a futile exercise. The models are learning nearly identical representations of the data, rendering their collective contribution redundant. The solution lies not in incremental tweaks but in exploiting the fundamental architectural differences between the models to generate novel, non-redundant features. CatBoost's primary competitive advantage and the key leverage point to break this collinearity resides in its sophisticated, native handling of categorical features through a mechanism known as Ordered Target Encoding, which is realized via its Categorical Target Statistics (CTR). Unlike LightGBM, which relies on grouping categories and can struggle with high-cardinality features, CatBoost processes categorical data in a way that is inherently resistant to target leakage and capable of discovering unique interaction patterns that other algorithms cannot replicate <Conversation History>[[19](https://apxml.com/courses/getting-started-with-gradient-boosting-algorithms/chapter-5-advanced-gradient-boosting-lightgbm-catboost/xgboost-vs-lightgbm-vs-catboost)]. By strategically configuring CatBoost's CTR parameters, it is possible to engineer a set of features that are fundamentally orthogonal to the signals captured by the preceding GLM and GBDT models, thereby injecting crucial diversity into the ensemble.

The core of CatBoost's categorical feature processing is the "Ordered Target Encoding" method [[4](https://medium.com/data-science/categorical-features-parameters-in-catboost-4ebd1326bee5)]. This technique is designed to calculate statistics for a categorical feature without leaking information from the current row's target value into its own encoding. The process begins with a random permutation of the entire dataset. For each row in this permuted order, the value of a categorical feature is encoded based on the average target value of all preceding rows in the permutation that share the same category [[4](https://medium.com/data-science/categorical-features-parameters-in-catboost-4ebd1326bee5)]. Because the calculation only considers past observations, there is no contamination from the current row's label, which is the essence of preventing target leakage. This ordered nature means that the encoding for any given category is not a simple static mean but a dynamic statistic that changes with the local distribution of the target variable throughout the dataset. This process is repeated for each fold in a cross-validation scheme, ensuring that the encoding for a test set object is always calculated based on a disjoint training set, further solidifying the protection against leakage [[3](https://catboost.ai/docs/en/references/training-parameters/ctr)]. This inherent mechanism gives CatBoost a significant edge in datasets rich with categorical variables, allowing it to build powerful, bespoke features that directly relate category membership to the outcome in a nuanced, non-linear fashion.

To move beyond this default behavior and actively engineer novel features, one must delve into the configuration of CatBoost's CTR parameters. The user's directive to prioritize identifying novel categorical combination strategies and prior settings is precisely the right approach. The `simple_ctr` parameter controls the transformation of the original categorical features, while `combinations_ctr` governs the creation of new features by combining existing ones [[1](https://catboost.ai/docs/en/references/training-parameters/), [4](https://medium.com/data-science/categorical-features-parameters-in-catboost-4ebd1326bee5)]. By enabling `combinations_ctr` and increasing the `max_ctr_complexity`, we instruct CatBoost to explore multi-way interactions between categorical features. Setting `max_ctr_complexity` to a value like 2 or 3 encourages the model to discover synergistic effects, such as a unique risk profile for passengers who are both "Loyal" customers and travel in "Business" class, an interaction that a standard GBDT might struggle to find without explicit feature engineering. The syntax for configuring these CTRs is complex, involving string-based descriptors that specify the CTR type, border counts, and other parameters [[3](https://catboost.ai/docs/en/references/training-parameters/ctr), [5](https://datascience.stackexchange.com/questions/27003/catboost-categorical-features-handling-options-ctr-settings)]. For example, a `simple_ctr` configuration might look like `'CtrType=BinarizedTargetMeanValue:CtrBorderCount=10'`, which applies a specific type of target statistic with a certain number of discretization points [[4](https://medium.com/data-science/categorical-features-parameters-in-catboost-4ebd1326bee5)]. Experimentation with different CTR types—such as `Counter`, `FloatTargetMeanValue`, or `FeatureFreq` (GPU only)—can yield different feature representations, though `BinarizedTargetMeanValue` is often a good starting point as it incorporates Bayesian smoothing [[4](https://medium.com/data-science/categorical-features-parameters-in-catboost-4ebd1326bee5)].

Regularization is another critical lever for controlling CTRs and preventing overfitting. CatBoost offers several mechanisms for this. The `counter_calc_method` parameter specifies how the internal counters for calculating target statistics are managed. The default 'SkipTest' method is generally recommended as it excludes validation objects from the calculation, which is a form of regularization that helps prevent overfitting on the validation set [[1](https://catboost.ai/docs/en/references/training-parameters/), [3](https://catboost.ai/docs/en/references/training-parameters/ctr)]. Furthermore, CatBoost employs a "Bayesian bootstrap" mechanism controlled by the `bagging_temperature` parameter [[2](https://catboost.ai/docs/en/concepts/parameter-tuning)]. When `bagging_temperature` is set to a value greater than 0, it introduces randomness into the CTR calculation, effectively performing a weighted averaging over different permutations of the data. This prevents any single category from having an overly dominant influence based on a small number of samples, promoting more robust and generalizable encodings [[1](https://catboost.ai/docs/en/references/training-parameters/)]. A typical starting value for this parameter is around 0.2, which adds a moderate level of stochasticity.

Perhaps the most powerful regularization tool is the use of Bayesian priors. The `Prior` component allows the user to specify a constant value that is added to the numerator and/or denominator of the target statistic calculation [[3](https://catboost.ai/docs/en/references/training-parameters/ctr), [4](https://medium.com/data-science/categorical-features-parameters-in-catboost-4ebd1326bee5)]. For a binary classification task, the raw target statistic for a category is the fraction of positive examples within that category. By applying a prior, such as `Prior=0.5/1.0`, this fraction is smoothed towards the global mean, pulling the estimate for rare categories with few samples closer to the overall average. This is equivalent to adding pseudo-counts and acts as a powerful regularizer against overfitting on noisy or sparse data. Multiple priors can even be specified to apply different levels of smoothing [[4](https://medium.com/data-science/categorical-features-parameters-in-catboost-4ebd1326bee5)]. The ability to fine-tune this smoothing via the `Prior` parameter gives the user direct control over the trade-off between fitting the data closely and maintaining model stability. The syntax for this can be a single number or a fraction, and it is applied to the target statistic calculation [[3](https://catboost.ai/docs/en/references/training-parameters/ctr)]. For GPU training, the format is restricted to two numbers separated by a slash [[3](https://catboost.ai/docs/en/references/training-parameters/ctr)].

To ensure the success of this strategy, several preparatory steps are necessary. First, the set of `cat_features` fed to CatBoost must be carefully curated. It is crucial to transform features before passing them to the model. For example, if a survey question has a rating from 0 to 5, one should explicitly convert the `0` rating into a separate nominal category (e.g., 'NoRating') rather than treating it as a numeric value of zero. This prevents the model from assuming an ordinal relationship where none may exist and allows it to learn a completely independent effect for the absence of a rating. All selected categorical features should be passed to CatBoost in their original string/object format; manual label encoding should be avoided, as this bypasses CatBoost's native, superior handling mechanism [[19](https://apxml.com/courses/getting-started-with-gradient-boosting-algorithms/chapter-5-advanced-gradient-boosting-lightgbm-catboost/xgboost-vs-lightgbm-vs-catboost)]. Additionally, parameters like `one_hot_max_size` can be used to force one-hot encoding for features with very low cardinality (e.g., size <= 10), which can sometimes be more efficient and avoids the overhead of CTR calculations for those features [[1](https://catboost.ai/docs/en/references/training-parameters/), [2](https://catboost.ai/docs/en/concepts/parameter-tuning)]. Conversely, `ignored_features` can be used to exclude any features that are deemed irrelevant [[1](https://catboost.ai/docs/en/references/training-parameters/)].

In conclusion, breaking the cycle of high collinearity with LightGBM requires a strategic deployment of CatBoost's unique capabilities. By moving beyond default settings and actively engineering Categorical Target Statistics, it is possible to generate a rich set of novel, non-redundant features. This is achieved by carefully selecting the categorical feature set, enabling combination features with an appropriate complexity level, and applying robust regularization through Bayesian priors and randomized estimation methods. This process, when combined with a GLM-margin architecture that keeps the linear inputs purely additive, ensures that CatBoost's contribution is truly orthogonal, enriching the ensemble with a distinct source of predictive power and paving the way for a more effective and well-calibrated meta-learning stage.

## Constrained Optimization for Probabilistic Calibration

The failure of an unconstrained linear Ridge regression meta-learner, which yielded a marginal improvement over a basic Nelder-Mead approach (0.95867 vs. 0.95883), is symptomatic of a deeper systemic issue: severe multicollinearity among the base models <Conversation History>. With a pairwise correlation coefficient of $r = 0.9981$, the design matrix of the meta-model exhibits an extreme condition number, exceeding $10^5$. This numerical instability makes the inversion of the matrix $X^T X$ highly sensitive to small perturbations in the data, leading to wildly oscillating and uninterpretable weights. While Ridge regression attempts to mitigate this by adding a penalty to the diagonal of the matrix, it does not impose sign constraints. In the presence of such high correlation, the optimizer can still assign large negative weights to some models in the ensemble. This is the root cause of the catastrophic probability miscalibration observed in the extreme tails ($p < 0.02$ or $p > 0.98$). A negative weight for a well-calibrated model acts as a counter-prediction, pushing probabilities away from the extremes and severely distorting the overall calibration curve. The solution to this problem is not a more complex variant of linear regression, but a shift in paradigm towards constrained optimization, where the solution space is restricted to physically meaningful and statistically stable configurations. The proposed benchmark of Non-Negative Least Squares (NNLS), Bounded Nelder-Mead optimization, and Isotonic Stacking represents a principled and comprehensive strategy to enforce positivity, maximize performance metrics under constraints, and apply powerful non-parametric corrections to restore proper calibration.

Non-Negative Least Squares (NNLS) provides the most direct and mathematically rigorous solution to the problem of negative weights. NNLS is a convex optimization problem whose goal is to find a solution vector $\mathbf{x}$ that minimizes the squared Euclidean norm of the residual, $||A\mathbf{x} - \mathbf{b}||_2^2$, subject to the constraint that all elements of $\mathbf{x}$ are non-negative ($\mathbf{x} \ge 0$) [[15](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.nnls.html)]. In the context of our meta-learner, the matrix $A$ is the feature matrix of OOF predictions from the base models, and the vector $\mathbf{b}$ is the true target labels from the OOF procedure <Conversation History>[[24](https://www.machinelearningmastery.com/out-of-fold-predictions-in-machine-learning/)]. By solving this NNLS problem, we find the set of weights that best combines the base models' predictions to match the true labels, while explicitly forbidding any model from acting as a negative predictor. This constraint alone is often sufficient to stabilize the optimization and prevent the corruption of probability distributions in the tails. The `scipy.optimize.nnls` function provides a highly efficient and reliable implementation of this algorithm, typically based on an active-set method that solves the Karush-Kuhn-Tucker (KKT) conditions for the problem [[15](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.nnls.html)]. After obtaining the non-negative weights, they can be normalized to sum to one to form a proper convex combination. This approach transforms the problem from one of simple least-squares fitting to one of constrained approximation, yielding a more robust and interpretable set of ensemble weights.

While NNLS operates in the least-squares framework, the ultimate goal of an ensemble is often to optimize a specific evaluation metric, such as Area Under the Receiver Operating Characteristic Curve (ROC-AUC). Bounded Nelder-Mead optimization offers a flexible alternative that allows for direct maximization of such metrics under hard constraints. The Nelder-Mead algorithm, available in SciPy's `optimize.minimize` function with `method='Nelder-Mead'`, is a derivative-free simplex-based search method [[16](https://www.kaggle.com/code/daisukelab/optimizing-ensemble-weights-using-simple), [17](https://docs.scipy.org/doc/scipy/reference/optimize.minimize-neldermead.html)]. Although the classic Nelder-Mead algorithm does not natively support bounds, the SciPy implementation provides a `bounds` parameter that clips the simplex vertices to stay within specified ranges [[17](https://docs.scipy.org/doc/scipy/reference/optimize.minimize-neldermead.html)]. To implement the desired constrained optimization, one would wrap the ROC-AUC calculation in a Python function that takes the weights as input. Inside this function, the weights are first clipped to be non-negative (e.g., `np.clip(weights, 0, None)`). If the sum of clipped weights becomes zero, the function returns a large penalty value. Otherwise, the weights are normalized to sum to one, and the weighted OOF predictions are computed. The ROC-AUC score is then calculated using a library like scikit-learn, and the negative of this score is returned (since `minimize` finds a minimum, not a maximum) <Conversation History>. The optimization is then performed over a bounded space where each weight is constrained between 0 and 1. To enforce the sum-to-one constraint, one could add a penalty term to the objective function that increases as the sum of weights deviates from one, or use a constrained optimization method that supports equality constraints. The user's suggestion of incorporating Dirichlet shrinkage priors toward uniform weights is an excellent stabilization technique. This can be implemented by adding a logarithmic penalty term to the objective function proportional to the dot product of the weights and the log of the weights, which encourages the optimizer to favor more balanced weight distributions and prevents any single model from dominating the ensemble [[18](https://www.kaggle.com/kava1/writeups)].

The third approach, Isotonic Stacking, represents a fundamentally different philosophy. Instead of optimizing weights, it focuses on correcting the calibration error of the ensemble's final predictions. Probability calibration refers to the property where a model's predicted probability reflects the true long-run proportion of positive cases [[13](https://towardsdatascience.com/you-think-80-means-80-why-prediction-probabilities-need-a-second-look-ebc8b650cf21/)]. For example, if a perfectly calibrated model predicts a probability of 0.8 for 1000 instances, approximately 800 of those instances should actually belong to the positive class. Isotonic regression is a non-parametric method that learns a piecewise-constant, monotonically non-decreasing function to map a classifier's raw scores to well-calibrated probabilities [[10](https://stats.stackexchange.com/questions/466722/understanding-probability-calibration-with-isotonic-regression-in-sklearn), [11](https://medium.com/data-science-at-microsoft/model-calibration-for-classification-tasks-using-python-1a7093b57a46)]. Its flexibility allows it to correct for any arbitrary monotonic distortion in the model's outputs, making it more powerful than parametric methods like Platt Scaling (sigmoid fitting), which assumes a sigmoid-shaped error curve [[12](https://blog.trainindata.com/probability-calibration-in-machine-learning/), [13](https://towardsdatascience.com/you-think-80-means-80-why-prediction-probabilities-need-a-second-look-ebc8b650cf21/)]. The isotonic regression problem is formulated as a constrained optimization: minimize the sum of weighted squared errors, $\sum w_i (q_i - y_i)^2$, where $q_i$ are the calibrated probabilities, subject to the monotonicity constraint $q_1 \le q_2 \le ... \le q_N$ and the bounds $0 \le q_i \le 1$ [[10](https://stats.stackexchange.com/questions/466722/understanding-probability-calibration-with-isotonic-regression-in-sklearn)]. This problem is efficiently solved using the Pool Adjacent Violators Algorithm (PAVA), which operates in linear time [[10](https://stats.stackexchange.com/questions/466722/understanding-probability-calibration-with-isotonic-regression-in-sklearn)]. In the context of our ensemble, isotonic regression can be applied as a final post-processing step. After combining the base models' OOF predictions using any initial weighting scheme (e.g., uniform or NNLS weights), the resulting OOF predictions serve as the input scores for an isotonic regressor. This regressor is trained on the OOF predictions and the true labels using scikit-learn's `CalibratedClassifierCV` with `method='isotonic'` and `cv=k` [[6](https://scikit-learn.org/stable/modules/calibration.html), [12](https://blog.trainindata.com/probability-calibration-in-machine-learning/)]. The resulting calibrated probabilities are then used for final predictions. This method is exceptionally effective at fixing miscalibration in the tails, where probabilistic distortions are often most pronounced [[13](https://towardsdatascience.com/you-think-80-means-80-why-prediction-probabilities-need-a-second-look-ebc8b650cf21/)]. It is important to note that isotonic regression is a non-parametric method that fits a step-wise non-decreasing function, making it effective for correcting monotonic distortions [[11](https://medium.com/data-science-at-microsoft/model-calibration-for-classification-tasks-using-python-1a7093b57a46)]. For smaller datasets, parametric methods like Sigmoid Scaling (Platt Scaling) are often preferred as they are less prone to overfitting [[6](https://scikit-learn.org/stable/modules/calibration.html), [11](https://medium.com/data-science-at-microsoft/model-calibration-for-classification-tasks-using-python-1a7093b57a46)].

In summary, the failure of unconstrained linear models due to multicollinearity necessitates a move towards constrained optimization. NNLS provides a principled, convex solution that guarantees non-negative weights. Bounded Nelder-Mead offers flexibility to directly optimize a performance metric like ROC-AUC under the critical non-negativity constraint. Finally, Isotonic Stacking serves as a powerful, non-parametric tool to directly fix calibration errors by learning a monotonic correction function for the ensemble's final predictions. Benchmarking these three methods will provide deep insights into the most effective way to combine the diverse signals from the base models into a single, highly accurate, and well-calibrated final prediction.

## Comparative Analysis of Constrained Meta-Learner Architectures

To effectively resolve the probability calibration failures stemming from severe multicollinearity, it is imperative to conduct a comparative analysis of the three proposed constrained optimization formulations for the meta-learner: Non-Negative Least Squares (NNLS), Bounded Nelder-Mead optimization, and Isotonic Stacking. Each method addresses the core problem from a different perspective—enforcing non-negativity, maximizing a custom metric under constraints, and correcting the functional form of the probability mapping, respectively. A systematic comparison of their theoretical foundations, implementation details, advantages, and disadvantages will guide the selection of the most suitable architecture for the final ensemble. The common prerequisite for all three is the construction of a meta-training dataset. This is accomplished by collecting out-of-fold (OOF) predictions from all base models (the GLM, the XGBoost/LightGBM pair, and CatBoost) during a k-fold cross-validation process. These OOF predictions form the feature matrix, $X_{meta}$, where each column corresponds to one base model's predictions, and each row corresponds to a sample in the training set. The target vector, $y_{meta}$, consists of the true labels for these same samples <Conversation History>[[24](https://www.machinelearningmastery.com/out-of-fold-predictions-in-machine-learning/)]. This OOF dataset is then used to train and benchmark each of the three meta-learners.

**Non-Negative Least Squares (NNLS)** stands out for its mathematical elegance and stability. As a convex optimization problem, it is guaranteed to find a global minimum, avoiding the pitfalls of local optima that plague derivative-free methods like Nelder-Mead [[15](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.nnls.html)]. The core advantage is the hard enforcement of non-negativity, which directly prevents the corruption of probability calibration caused by negative weights. This makes it a robust and safe baseline. However, its reliance on minimizing mean squared error implicitly assumes a linear relationship between the OOF predictions and the true target. If the optimal combination is non-linear, NNLS may not be able to capture it, potentially failing to maximize the actual competition metric like log-loss or ROC-AUC. Its implementation is straightforward via `scipy.optimize.nnls`, which is highly optimized and reliable [[15](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.nnls.html)]. The main disadvantage is its potential inability to achieve the highest possible performance if the underlying relationship is non-linear.

**Bounded Nelder-Mead Optimization** offers maximum flexibility at the cost of increased complexity and potential instability. By allowing the user to define a custom objective function, it enables the direct optimization of the target evaluation metric, such as ROC-AUC, which is the ultimate goal [[18](https://www.kaggle.com/kava1/writeups)]. This is a significant advantage over NNLS, which optimizes MSE. The ability to incorporate regularization, such as the suggested Dirichlet priors, helps stabilize the optimization and prevent over-concentration of weights on a single model, a common failure mode in ensembles [[18](https://www.kaggle.com/kava1/writeups)]. The main drawback is that Nelder-Mead is a heuristic algorithm and is not guaranteed to find the global optimum; it can get stuck in local minima/maxima [[16](https://www.kaggle.com/code/daisukelab/optimizing-ensemble-weights-using-simple)]. Its convergence can be slow, especially in higher dimensions, and the quality of the result is often dependent on the initial simplex and the chosen bounds. Furthermore, enforcing the sum-to-one constraint is not trivial with this method and typically requires either a penalty function or a change of variables (e.g., using the softmax function), which can complicate the optimization surface. Despite these challenges, its ability to directly chase the target metric makes it a powerful contender, especially if the relationship between OOF predictions and the final score is complex.

**Isotonic Stacking** represents a paradigm shift from weight optimization to functional correction. Instead of asking "how much should I trust each model?", it asks "what is the correct mapping from the combined model's output to a calibrated probability?". This approach is particularly potent for addressing the specific calibration failures in the probability tails ($p < 0.02$ or $p > 0.98$) that were identified <Conversation History>. Since it does not assume a parametric form for the calibration curve (unlike Platt scaling, which assumes a sigmoid), it can correct for a wide variety of distortion shapes [[11](https://medium.com/data-science-at-microsoft/model-calibration-for-classification-tasks-using-python-1a7093b57a46), [13](https://towardsdatascience.com/you-think-80-means-80-why-prediction-probabilities-need-a-second-look-ebc8b650cf21/)]. The primary implementation is through `sklearn.calibration.CalibratedClassifierCV` with `method='isotonic'` and `cv=k` [[6](https://scikit-learn.org/stable/modules/calibration.html), [12](https://blog.trainindata.com/probability-calibration-in-machine-learning/)]. This class handles the OOF prediction collection and fitting of the calibrator automatically. The main disadvantage of isotonic regression is its tendency to overfit on small datasets, as it can produce a highly granular, step-wise function that follows noise rather than the true underlying pattern [[6](https://scikit-learn.org/stable/modules/calibration.html), [11](https://medium.com/data-science-at-microsoft/model-calibration-for-classification-tasks-using-python-1a7093b57a46)]. While the dataset here is large (700k-830k rows), the OOF predictions for the meta-model might still be subject to this if the base models are too confident and clustered. Another potential issue is the perception of "jaggedness" in the calibration curve, which is often an artifact of uniform binning and dataset imbalance rather than a flaw in the algorithm itself [[8](https://stats.stackexchange.com/questions/493393/should-scikit-learn-calibratedclassifiercv-isotonic-mode-use-bucketed-rates-inst)]. However, its proven effectiveness in fixing calibration errors makes it an indispensable tool in the arsenal.

In conclusion, no single method is universally superior. NNLS serves as an excellent, stable, and interpretable baseline that guarantees non-negative contributions from all models. Bounded Nelder-Mead offers the tantalizing possibility of directly optimizing the target metric but comes with the risks of local optima and implementation complexity. Isotonic Stacking is a specialized tool, arguably the best for the job of fixing calibration issues, especially in the tails. A prudent strategy would be to implement all three and compare their performance on a held-out validation set. It is also possible to combine them: for instance, using NNLS weights to create an initial, well-calibrated OOF prediction and then applying isotonic regression as a final fine-tuning step. This hybrid approach could leverage the strengths of both linear stability and non-parametric correction. The benchmarking process will provide empirical evidence to determine whether the marginal gain from optimizing a complex metric with Nelder-Mead justifies its complexity, or whether the robust, targeted correction of isotonic regression is the more effective path to a well-calibrated and high-scoring ensemble.

This function generates leak-free out-of-fold logit margins using a regularized Logistic Regression with spline transformations for continuous variables.

def generate_glm_margins(X_train, y_train, cont_features, cat_features, cv_folds=5):
    """
    Generate leak-free OOF logit margins using a GLM with splines.
    """
    # For simplicity, let's assume X_train is a DataFrame
    oof_glm_margins = np.zeros(len(X_train))
    kf = KFold(n_splits=cv_folds, shuffle=True, random_state=42)
    
    for train_idx, val_idx in kf.split(X_train):
        X_tr, X_val = X_train.iloc[train_idx], X_train.iloc[val_idx]
        y_tr, y_val = y_train.iloc[train_idx], y_train.iloc[val_idx]
        
        # Build a pipeline-like preprocessing (simplified)
        # Apply splines to continuous features
        spline_transformer = SplineTransformer(n_knots=5, degree=3)
        X_tr_splines = spline_transformer.fit_transform(X_tr[cont_features])
        X_val_splines = spline_transformer.transform(X_val[cont_features])
        
        # One-hot encode categorical features
        X_tr_cats = pd.get_dummies(X_tr[cat_features], drop_first=True)
        X_val_cats = pd.get_dummies(X_val[cat_features], drop_first=True)
        
        # Align columns to avoid mismatch
        X_tr_cats, X_val_cats = X_tr_cats.align(X_val_cats, join='outer', fill_value=0, axis=1)
        X_val_cats, X_tr_cats = X_val_cats.align(X_tr_cats, join='outer', fill_value=0, axis=1)
        
        # Combine features
        X_tr_combined = np.hstack([X_tr_splines.toarray(), X_tr_cats.values])
        X_val_combined = np.hstack([X_val_splines.toarray(), X_val_cats.values])
        
        # Fit GLM
        glm = LogisticRegression(penalty='l2', max_iter=1000, C=0.1)
        glm.fit(X_tr_combined, y_tr)
        
        # Predict log-odds (margin) on validation fold
        oof_glm_margins[val_idx] = glm.predict_log_proba(X_val_combined)[:, 1] # Use proba then logit?
        # Correction: predict_log_odds directly is tricky. Better to predict proba then logit.
        # Let's adjust:
        # oof_glm_margins[val_idx] = np.log(glm.predict_proba(X_val_combined)[:, 1] / (1 - glm.predict_proba(X_val_combined)[:, 1]))
        
    return oof_glm_margins

def train_catboost(X_train, y_train, X_test, cat_features_indices):

def train_nnls_ensemble(X_meta, y_meta):
    # NNLS expects float64 for stability
    X_meta = X_meta.astype(np.float64)
    y_meta = y_meta.astype(np.float64)
    weights, _ = nnls(X_meta, y_meta)
    weights /= weights.sum() # Normalize to sum to 1

## 2. Bounded Nelder-Mead for AUC
from scipy.optimize import minimize
def neg_auc_objective(weights, X, y):
    weights = np.clip(weights, 0, None)
    if weights.sum() == 0:
        return np.inf
    w = weights / weights.sum()
    preds = X @ w
    return -roc_auc_score(y, preds) # Negate for minimization

def train_bounded_nelder_mead_ensemble(X_meta, y_meta):
    n_models = X_meta.shape[1]
    initial_guess = np.ones(n_models) / n_models
    bounds = [(0, None) for _ in range(n_models)] # Non-negativity
    
    result = minimize(
        neg_auc_objective,
        initial_guess,
        args=(X_meta, y_meta),
        method='Nelder-Mead',
        bounds=bounds,
        options={'maxiter': 1000}
    )
    weights = result.x
    weights /= weights.sum()
    return weights

**Best Practices Summary:**
*   **Cross-Validation for Leaks:** The entire pipeline, from feature generation to meta-model training, must rely on OOF predictions to prevent data leakage and ensure honest performance estimation [[24](https://www.machinelearningmastery.com/out-of-fold-predictions-in-machine-learning/)].

*   **Regularization is Key:** Aggressive regularization (L2 in GLM, `l2_leaf_reg` in CatBoost, early stopping) is crucial to prevent any single model from dominating and to maintain generalization.
*   **Iterative Refinement:** Start with the NNLS baseline. Then, experiment with Bounded Nelder-Mead to see if it can squeeze out more performance on the target metric. Finally, apply Isotonic Stacking as a powerful post-hoc calibration tool to fix any remaining miscalibration artifacts.
*   **Monitor Calibration:** Throughout the process, evaluate not just the primary metric (e.g., AUC) but also calibration metrics like the Brier Score and Expected Calibration Error (ECE) to ensure the final probabilities are well-calibrated [[9](https://github.com/scikit-learn/scikit-learn/discussions/21785), [12](https://blog.trainindata.com/probability-calibration-in-machine-learning/)].
